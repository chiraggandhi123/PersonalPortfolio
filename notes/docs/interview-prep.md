## 0 · Python for AI

- **"Why use a virtual environment?"** → Each project gets its own package versions, so upgrading one project's `openai` doesn't break another. · [Python Setup (VS Code, first script)](./00-python-for-ai/01-python-setup.md)
- **"Is Python statically typed?"** → No, it's dynamically typed. Type hints are optional and checked by tools, not the interpreter. · [Variables, Data Types & f-strings](./00-python-for-ai/02-variables-data-types-f-strings.md)
- **"How is a chat conversation represented for the OpenAI API?"** → A list of dicts, each with `role` and `content`. · [Data Structures (list, dict, set, tuple)](./00-python-for-ai/03-data-structures.md)
- **"How would you stop an agent looping forever?"** → Cap iterations in the `while` loop (max steps), plus a timeout or token budget. · [Control Flow & Comprehensions](./00-python-for-ai/04-control-flow-comprehensions.md)
- **"What's wrong with `def f(x=[])`?"** → The list is created once and shared across calls; use `None` and create it inside. · [Functions & Arguments](./00-python-for-ai/05-functions-arguments.md)
- **"What is `self`?"** → The instance the method is called on; Python passes it automatically as the first argument. · [Object-Oriented Python (enough to read frameworks)](./00-python-for-ai/06-object-oriented-python.md)
- **"Which LLM API errors should you retry?"** → Rate limits, timeouts, connection errors and 5xx. Not auth or bad-request errors. · [Error Handling & Files (JSON)](./00-python-for-ai/07-error-handling-files.md)
- **"Why Pydantic in LLM apps?"** → LLM output is untrusted text; Pydantic defines the expected shape, generates the schema for the API, and validates the result into a typed object. · [Pydantic (data validation & structured outputs)](./00-python-for-ai/08-pydantic.md)
- **"How do you make a Python project reproducible?"** → Venv per project, pinned dependencies in a lockfile or `requirements.txt`, a stated Python version, and ideally a Dockerfile. · [Environments & Packages (venv, pip, requirements)](./00-python-for-ai/09-environments-packages.md)
- **"How do you manage API keys in a Python app?"** → Environment variables; `.env` + `python-dotenv` locally (gitignored), a secrets manager in production, validated at startup. · [API Keys & .env (never hard-code secrets)](./00-python-for-ai/10-api-keys-env.md)
- **"What does an LLM SDK actually do?"** → Builds an HTTP POST with your key and JSON body, sends it, handles retries/errors, and parses the JSON into typed objects. · [Calling an API (requests + JSON)](./00-python-for-ai/11-calling-an-api.md)
- **"Why use async for LLM apps?"** → Calls are I/O-bound; async lets you run many concurrently on one thread, cutting latency for batches and handling many users. · [Async Basics You'll See in Agents](./00-python-for-ai/12-async-basics-youll-see-in-agents.md)
- **"`git pull` vs `git fetch`?"** → `fetch` downloads remote changes without touching your files; `pull` fetches and merges them into your branch. · [Git & GitHub (commit, push, README)](./00-python-for-ai/13-git-github.md)
- **"Why does my Streamlit variable reset?"** → The script reruns on every interaction; store it in `st.session_state`. · [Build a UI Fast (Streamlit + a little FastAPI)](./00-python-for-ai/14-build-a-ui-fast.md)

## 1 · LLM Basics

- **"How does ChatGPT/Claude generate text?"** → Autoregressively: predicts a probability distribution over next tokens, samples one, appends it, repeats until a stop token. · [What Is an LLM (tokens & next-token prediction)](./01-llm-basics/01-what-is-an-llm.md)
- **"Explain attention simply."** → Each token scores every other token for relevance (query vs. key), then takes a weighted mix of their information (values). · [Transformers & Attention (the intuition)](./01-llm-basics/02-transformers-attention.md)
- **"Why are output tokens pricier than input?"** → Input is processed in one parallel pass; output is generated sequentially, one forward pass per token. · [Tokens, Context Windows & Cost](./01-llm-basics/03-tokens-context-windows-cost.md)
- **"What is an embedding?"** → A dense vector representing meaning; similar texts map to nearby vectors. · [Embeddings (meaning as vectors)](./01-llm-basics/04-embeddings.md)
- **"How would you choose a model for a new feature?"** → Define the task and constraints (latency, cost, privacy), prototype with a strong model, build an eval set, then test cheaper models and pick the smallest that passes. · [The Model Landscape (GPT, Claude, Gemini, Llama)](./01-llm-basics/05-the-model-landscape.md)
- **"What does temperature do?"** → Scales logits before softmax; lower sharpens the distribution (more deterministic), higher flattens it (more random). · [Sampling: Temperature & Top-p](./01-llm-basics/06-sampling-temperature-top-p.md)
- **"Why do LLMs hallucinate?"** → They optimize for plausible next tokens, have no built-in fact lookup, and are rarely trained to abstain. · [Hallucinations & Limitations](./01-llm-basics/07-hallucinations-limitations.md)
- **"How does a chatbot remember previous messages?"** → It doesn't — the app resends the conversation history in each request. · [Your First Chatbot (chat history + an LLM API)](./01-llm-basics/08-your-first-chatbot.md)

## 2 · Calling Models

- **"Do LLM APIs remember previous requests?"** → No, they're stateless; the client resends the conversation each time (unless you opt into server-side state like OpenAI's `previous_response_id`). · [Chat APIs (OpenAI, Anthropic, Gemini)](./02-calling-models/01-chat-apis.md)
- **"What's the difference between the system and user role?"** → System is developer-level instruction that applies to the whole conversation and outranks the user; user is the end user's input. · [Messages & Roles (system, user, assistant)](./02-calling-models/02-messages-roles.md)
- **"Does streaming make the model faster?"** → No, total generation time is about the same; it lowers time to first token, so the app feels faster. · [Streaming Responses](./02-calling-models/03-streaming-responses.md)
- **"How do you get reliable JSON from an LLM?"** → Use structured outputs with a schema (e.g. Pydantic via `parse`), handle refusals and truncation, and validate the values. · [Structured Outputs (JSON mode & schemas)](./02-calling-models/04-structured-outputs.md)
- **"Does the model execute the function?"** → No; it outputs the function name and JSON arguments, your code runs it and sends the result back. · [Tool / Function Calling](./02-calling-models/05-tool-function-calling.md)
- **"Which LLM API errors should you retry?"** → Rate limits, timeouts, connection errors and 5xx; not 400/401/403/404, which fail the same way every time. · [Errors, Retries & Rate Limits](./02-calling-models/06-errors-retries-rate-limits.md)
- **"How do you track the cost of an LLM feature?"** → Log usage per call with feature/user tags, multiply by the model's per-token price, and aggregate in a dashboard or tracing tool. · [Tracking Tokens & Cost](./02-calling-models/07-tracking-tokens-cost.md)
- **"Why would you run an LLM locally instead of using an API?"** → Data privacy, no per-token cost, offline use, and full control; at the cost of smaller models and your own hardware limits. · [Running Models Locally (Ollama)](./02-calling-models/08-running-models-locally.md)
- **"How would you avoid vendor lock-in with LLM providers?"** → Put calls behind one interface (LiteLLM, LangChain, or an OpenAI-compatible gateway), keep model names in config, and keep an eval set to compare providers. · [Provider-Agnostic Clients (LiteLLM, LangChain)](./02-calling-models/09-provider-agnostic-clients.md)

## 3 · Prompting & LLM Apps

- **"What makes a good prompt?"** → Clear task, relevant context, constraints, delimited input data, an explicit output format and, if needed, an example. · [Prompt Engineering Basics](./03-prompting-llm-apps/01-prompt-engineering-basics.md)
- **"When do you use few-shot over zero-shot?"** → When the format, style or label boundaries are off. Examples show what instructions struggle to describe. · [Zero-Shot, Few-Shot & Chain-of-Thought](./03-prompting-llm-apps/02-zero-shot-few-shot-chain-of-thought.md)
- **"What goes in a system prompt?"** → Role, task, rules and edge-case handling, output style, and dynamic context such as the date. · [System Prompts & Personas](./03-prompting-llm-apps/03-system-prompts-personas.md)
- **"How do you manage prompts in production?"** → Store them as versioned files or in a registry, log the version with each call, and run an eval set before switching versions. · [Prompt Templates & Versioning](./03-prompting-llm-apps/04-prompt-templates-versioning.md)
- **"Structured outputs guarantee the schema. Why still validate?"** → The schema guarantees shape, not correctness. Business rules, cross-field logic and real-world truth still need checks. · [Parsing & Validating Output (Pydantic)](./03-prompting-llm-apps/05-parsing-validating-output.md)
- **"How does a chatbot remember previous messages?"** → It doesn't; the app resends the relevant history with each request. · [Conversation Memory](./03-prompting-llm-apps/06-conversation-memory.md)
- **"What is LCEL?"** → A way to compose LangChain components with the pipe operator into runnables that support invoke, stream and batch. · [Building LLM Apps with LangChain](./03-prompting-llm-apps/07-building-llm-apps-with-langchain.md)
- **"Streamlit or FastAPI for an LLM product?"** → Streamlit for prototypes and internal tools; FastAPI as the backend for production, with any UI on top. · [Streamlit & FastAPI Front-Ends](./03-prompting-llm-apps/08-streamlit-fastapi-front-ends.md)
- **"How do you handle API keys in a deployed app?"** → Environment variables or a secrets manager, never in code or the client; rotate on leaks. · [Deploying an LLM App](./03-prompting-llm-apps/09-deploying-an-llm-app.md)
- **"What is prompt injection?"** → Untrusted text that makes the model follow attacker instructions instead of the developer's, either typed directly or hidden in processed content. · [Prompt Injection Basics](./03-prompting-llm-apps/10-prompt-injection-basics.md)

## 4 · Retrieval (RAG)

- **"What problem does RAG solve?"** → It gives the model up-to-date and private knowledge at query time, which reduces hallucination and allows citations, without retraining. · [Introduction](./04-rag/01-introduction.md)
- **"Explain RAG in one sentence."** → Search a knowledge base for passages relevant to the question and give them to the LLM in the prompt so it answers from them. · [Introduction to RAG](./04-rag/02-introduction-to-rag.md)
- **"Walk me through the components of a RAG pipeline."** → Loader, splitter, embedding model and vector store for indexing; retriever, prompt, LLM and parser for querying. · [Core Components in RAG](./04-rag/03-core-components-in-rag.md)
- **"Why use a virtual environment per project?"** → Different projects need different library versions; isolation prevents conflicts and makes setups reproducible. · [VS Code & Anaconda Setup](./04-rag/04-vs-code-anaconda-setup.md)
- **"How do you handle tables in PDFs for RAG?"** → Use a layout-aware parser that outputs tables as Markdown or HTML, keep each table in one chunk, and optionally add an LLM-written summary for retrieval. · [Data Ingestion & Parsing](./04-rag/05-data-ingestion-parsing.md)
- **"Why not just store embeddings in a numpy array?"** → Fine for small data, but you lose ANN speed at scale, metadata filtering, updates, persistence and concurrency. · [Vector Embedding & Vector Databases](./04-rag/06-vector-embedding-vector-databases.md)
- **"FAISS vs. Chroma?"** → FAISS is an in-memory similarity search library; Chroma is a lightweight database with persistence, metadata filtering and CRUD. · [Vector Stores & Vector Databases](./04-rag/07-vector-stores-vector-databases.md)
- **"How do you pick chunk size?"** → Start around 500–1000 characters with some overlap, respect document structure, then tune by measuring retrieval on a test set. · [Advanced Chunking & Preprocessing](./04-rag/08-advanced-chunking-preprocessing.md)
- **"Why hybrid search?"** → Dense search handles paraphrases, BM25 handles exact terms like IDs and names; combining them covers both failure modes. · [Hybrid Search Strategies](./04-rag/09-hybrid-search-strategies.md)
- **"How do you handle follow-up questions in a RAG chatbot?"** → Condense the follow-up and chat history into a standalone question before retrieval. · [Query Enhancement](./04-rag/10-query-enhancement.md)
- **"How would you do RAG over PDFs with charts?"** → Extract images, caption them with a vision model, embed the captions with a pointer to the image, and pass the original image to a VLM at answer time. · [Multi-Modal RAG](./04-rag/11-multi-modal-rag.md)
- **"What makes something an agent rather than a chain?"** → The LLM decides the control flow: which tool to call next and when to stop, in a loop. · [AI Agents & Agentic AI (intro)](./04-rag/12-ai-agents-agentic-ai.md)
- **"What changed in LangChain v1?"** → A smaller core focused on agents: `create_agent` built on LangGraph, middleware, standard content blocks, and legacy chains moved to `langchain-classic`. · [Updated LangChain (v1) Hands-On](./04-rag/13-updated-langchain.md)
- **"Why LangGraph instead of a LangChain chain?"** → Chains are linear (DAGs); LangGraph supports loops, branching, persistence and human-in-the-loop, which agents and self-correcting RAG need. · [LangGraph Basics](./04-rag/14-langgraph-basics.md)
- **"LangChain vs. LangGraph?"** → LangChain provides components and simple chains; LangGraph orchestrates them with explicit state, loops and persistence for complex agents. · [LangChain vs LangGraph vs LangSmith vs Langflow](./04-rag/15-langchain-vs-langgraph-vs-langsmith-vs-langflow.md)
- **"What are the core components of an agent?"** → A model, tools, state/memory and a control loop, plus guardrails such as step limits. · [Agents Architecture](./04-rag/16-agents-architecture.md)
- **"What makes RAG agentic?"** → The LLM decides whether to retrieve, from where, judges the results and can retry, instead of a fixed retrieve-then-generate pipeline. · [Agentic RAG](./04-rag/17-agentic-rag.md)
- **"Agentic vs. autonomous RAG?"** → Agentic decides whether and where to retrieve; autonomous also plans sub-questions and iterates until it judges the evidence complete. · [Autonomous RAG](./04-rag/18-autonomous-rag.md)
- **"Why multi-agent instead of one agent with many tools?"** → Smaller prompts and tool sets per agent improve tool choice and keep context focused; parts can be developed and tested separately. · [Multi-Agent RAGs](./04-rag/19-multi-agent-rags.md)
- **"What problem does CRAG solve?"** → Plain RAG generates from whatever is retrieved, even if irrelevant; CRAG detects bad retrieval and corrects it before generation. · [Corrective RAG (CRAG)](./04-rag/20-corrective-rag.md)
- **"Adaptive RAG in one line?"** → Classify query complexity first, then use no retrieval, single-step or multi-step retrieval accordingly. · [Adaptive RAG & Self-RAG](./04-rag/21-adaptive-rag-self-rag.md)
- **"Short-term vs. long-term memory in LangGraph?"** → Short-term is thread state saved by a checkpointer; long-term is a store shared across threads, usually per user. · [RAG with Persistent Memory](./04-rag/22-rag-with-persistent-memory.md)
- **"Exact vs. semantic caching?"** → Exact matches identical text, safe but low hit rate; semantic matches by embedding similarity, higher hit rate but risks returning answers to different questions. · [Cache RAG with LangGraph](./04-rag/23-cache-rag-with-langgraph.md)
- **"What is vectorless RAG?"** → Retrieval without embeddings: the LLM reads a structured index of a document (like a table of contents with summaries) and reasons about which sections to read. · [VectorLess RAG with PageIndex](./04-rag/24-vectorless-rag-with-pageindex.md)
- **"Where do you put guardrails in a RAG app?"** → On the input (safety, injection, scope, PII), on retrieved context (untrusted data, access control) and on the output (groundedness, PII, policy). · [Guardrails](./04-rag/25-guardrails.md)
- **"Why use an LLM gateway?"** → One API across providers, plus central fallbacks, retries, rate limits, budgets, caching, key management and logging. · [LLM Gateways](./04-rag/26-llm-gateways.md)
- **"How do you evaluate a RAG system?"** → A golden dataset, retrieval metrics (hit rate, MRR) and generation metrics (faithfulness, relevance, correctness) via LLM judges, run on every change. · [Chatbot & RAG Evaluation](./04-rag/27-chatbot-rag-evaluation.md)
- **"When is a graph DB better than a vector DB for RAG?"** → For relationship-heavy, multi-hop and aggregate questions; vectors are better for fuzzy semantic text lookup. · [Graph Databases & Cypher (LangChain)](./04-rag/28-graph-databases-cypher.md)
- **"How do you build a knowledge graph from unstructured text?"** → LLM extraction (e.g. `LLMGraphTransformer`) with a constrained schema, entity resolution, then load with MERGE into a graph DB. · [Practical GraphDB with LangChain](./04-rag/29-practical-graphdb-with-langchain.md)
- **"Walk me through a production RAG system."** → Offline ingestion (parse, chunk, embed, index with metadata and incremental updates); online query (rewrite, hybrid retrieve, rerank, generate with citations); API + UI; evals and tracing. · [End-to-End RAG Document Search Project](./04-rag/30-end-to-end-rag-document-search-project.md)

## 5 · Advanced & Production RAG

- **"Why does naive RAG hallucinate even with a good index?"** → Retrieval can return irrelevant chunks and nothing checks them; the model fills gaps from memory unless told to refuse and verified. · [Limits of Basic RAG (where naive fails)](./05-advanced-rag/01-limits-of-basic-rag.md)
- **"What does CRAG add to RAG?"** → A relevance check on retrieved docs, plus corrective actions: rewrite and retry, or fall back to another source. · [Corrective RAG (CRAG)](./05-advanced-rag/02-corrective-rag.md)
- **"What's the core idea of Self-RAG?"** → The system decides when to retrieve and critiques its own answer for support and usefulness, looping when checks fail. · [Self-RAG (model decides when to retrieve)](./05-advanced-rag/03-self-rag.md)
- **"How do you stop the LLM running DROP TABLE?"** → A read-only DB role is the real guarantee; add parser validation (single SELECT, allowlisted tables) and timeouts. Prompts alone aren't enough. · [Text2SQL (query a database safely)](./05-advanced-rag/04-text2sql.md)
- **"Exact vs. semantic cache?"** → Exact matches identical requests (safe, low hit rate); semantic matches similar meaning (higher hit rate, risk of wrong answers, needs a tuned threshold). · [Caching & LLM Gateways (Redis, cost/latency)](./05-advanced-rag/05-caching-llm-gateways.md)
- **"What's unique about guardrails for RAG vs. a plain chatbot?"** → Retrieved content is a third attack surface (indirect injection), and access control must be enforced at retrieval. · [RAG Guardrails (input/output filtering)](./05-advanced-rag/06-rag-guardrails.md)
- **"How do you evaluate a RAG system?"** → A versioned eval set; retrieval metrics (context precision/recall, hit rate) and generation metrics (faithfulness, relevancy, correctness) scored separately; run on every change against a baseline. · [RAG Evaluation (faithfulness, relevance, eval sets)](./05-advanced-rag/07-rag-evaluation.md)
- **"Why LangGraph over a LangChain chain for RAG?"** → It supports cycles, branching and persistent state, which corrective and self-reflective RAG need. · [Orchestrating RAG with LangGraph](./05-advanced-rag/08-orchestrating-rag-with-langgraph.md)
- **"A user says the bot gave a wrong answer. Walk me through debugging."** → Pull the trace; check if the answer is in the corpus, then whether it was chunked well, retrieved, kept after reranking, and used by the model. Fix that stage and add an eval case. · [RAG Failure Modes & Debugging](./05-advanced-rag/09-rag-failure-modes-debugging.md)

## 6 · Fine-Tuning & Open Models

- **"RAG or fine-tuning for a chatbot over company docs?"** → RAG. Docs change, answers need citations, and fine-tuning doesn't reliably inject facts. · [Prompt vs RAG vs Fine-Tune (the decision)](./06-fine-tuning/01-prompt-vs-rag-vs-fine-tune.md)
- **"Give me a strong case for fine-tuning."** → A high-volume narrow task (e.g. ticket classification) where a fine-tuned small model matches a big model's accuracy at a fraction of the cost and latency. · [When to Fine-Tune (and when not to)](./06-fine-tuning/02-when-to-fine-tune.md)
- **"What format would you use for fine-tuning data?"** → Chat-format JSONL with system/user/assistant messages, matching the production prompt. · [Datasets for Fine-Tuning (instruction/chat)](./06-fine-tuning/03-datasets-for-fine-tuning.md)
- **"Explain LoRA in one breath."** → Freeze the model, learn a low-rank update `B·A` for selected weight matrices, so you train well under 1% of parameters with similar quality. · [LoRA & QLoRA (parameter-efficient tuning)](./06-fine-tuning/04-lora-qlora.md)
- **"How do you run an open model with Hugging Face?"** → `AutoTokenizer` and `AutoModelForCausalLM.from_pretrained`, apply the chat template, call `generate`, decode only the new tokens. · [Hugging Face Transformers (load, tokenize, infer)](./06-fine-tuning/05-hugging-face-transformers.md)
- **"How would you try Llama without a GPU?"** → Ollama locally for small sizes, or a hosted provider like Groq or Together via the OpenAI SDK. · [Running Open Models (Llama via Ollama/Groq)](./06-fine-tuning/06-running-open-models.md)
- **"How do you know your fine-tune worked?"** → It beats a well-prompted base model on a held-out set with task metrics, without regressions, at acceptable cost and latency. · [Evaluating a Fine-Tune](./06-fine-tuning/07-evaluating-a-fine-tune.md)
- **"How would you serve a fine-tuned Llama in production?"** → vLLM (or TGI) on a GPU with an OpenAI-compatible endpoint, behind a FastAPI gateway for auth, validation and logging, with versioned models and a fallback. · [Serving a Fine-Tuned Model Behind an API](./06-fine-tuning/08-serving-a-fine-tuned-model-behind-an-api.md)

## 7 · Agentic AI

- **"What do you need to know before building agents?"** → Python, how chat APIs and tool calling work, and basic deployment. Agent frameworks sit on top of those. · [Course Plan and Prerequisites](./07-agentic-ai/00-course/a-orientation/01-course-plan-and-prerequisites.md)
- **"Workflow or agent: how do you choose?"** → Use a workflow when the steps are known and stable; use an agent when the path depends on the input and can't be enumerated. Prefer the simpler option. · [Agentic AI Learning Roadmap](./07-agentic-ai/00-course/a-orientation/02-agentic-ai-learning-roadmap.md)
- **"What makes an LLM application 'agentic'?"** → The model chooses its next action in a loop, using tools and observations, instead of following a fixed sequence written in code. · [From LLMs to Agentic AI](./07-agentic-ai/00-course/b-foundations/01-from-llms-to-agentic-ai.md)
- **"What are the core components of an AI agent?"** → An LLM to reason, tools to act, memory for context, a loop or planner to sequence steps, and guardrails to bound behavior. · [Agent Characteristics and Components](./07-agentic-ai/00-course/b-foundations/02-agent-characteristics-and-components.md)
- **"Why use async in an agent?"** → Agents mostly wait on model and tool calls; async runs independent calls concurrently and lets one server handle many users. · [Async Programming for Agents](./07-agentic-ai/00-course/c-python-for-agents/01-async-programming-for-agents.md)
- **"Why use Pydantic in agent code?"** → It turns untrusted model output into typed objects at the boundary, with clear errors when the model gets it wrong. · [Pydantic for Agents](./07-agentic-ai/00-course/c-python-for-agents/02-pydantic-for-agents.md)
- **"What does `create_agent` do?"** → It wires a chat model and tools into a loop graph: call the model, run any requested tools, feed results back, stop when the model answers without tool calls. · [Single Agent with LangChain](./07-agentic-ai/00-course/d-langchain-agents/01-single-agent-with-langchain.md)
- **"When would you use multiple agents instead of one?"** → When roles need different tools or instructions and a single agent's prompt and toolset has grown too big to behave reliably. · [Multi-Agent Research Assistant with LangChain](./07-agentic-ai/00-course/d-langchain-agents/02-multi-agent-research-assistant-with-langchain.md)
- **"LangChain vs. LangGraph in one line?"** → LangChain gives you components and a prebuilt agent; LangGraph lets you build any stateful, looping control flow as a graph. · [LangChain vs LangGraph](./07-agentic-ai/00-course/e-langgraph-core/01-langchain-vs-langgraph.md)
- **"What are the building blocks of a LangGraph app?"** → State, nodes, edges (including conditional ones) and compilation, optionally with a checkpointer. · [LangGraph Core Components](./07-agentic-ai/00-course/e-langgraph-core/02-langgraph-core-components.md)
- **"Workflow vs. agent in LangGraph?"** → A workflow has paths defined by your edges; an agent lets the model choose the next step, usually a model–tools loop. · [LangGraph Workflows](./07-agentic-ai/00-course/e-langgraph-core/03-langgraph-workflows.md)
- **"What's the minimal LangGraph chatbot?"** → A state with an `add_messages` list, one node that calls the model on the messages, and START → node → END edges. · [Chatbot Skeleton in LangGraph](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/01-chatbot-skeleton-in-langgraph.md)
- **"How does a LangGraph chatbot remember conversations?"** → A checkpointer saves state per `thread_id`; each call loads the latest checkpoint, adds the new input and saves again. · [Agent Persistence](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/02-agent-persistence.md)
- **"How do you stream tokens from a LangGraph graph?"** → `graph.stream(input, config, stream_mode="messages")` yields `(chunk, metadata)`; render `chunk.content` and filter by `metadata["langgraph_node"]`. · [Streaming & Chat Threading](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/03-streaming-chat-threading.md)
- **"How do you enable LangSmith tracing for a LangGraph app?"** → Set `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY` and optionally `LANGSMITH_PROJECT`; LangChain and LangGraph runs are traced automatically. · [Tracing the Chatbot with LangSmith](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/04-tracing-the-chatbot-with-langsmith.md)
- **"How do you add tools to a LangGraph chatbot?"** → Bind tools to the model, add a `ToolNode`, route from the model node with `tools_condition`, and add an edge from tools back to the model. · [Tools in the Agentic Chatbot](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/05-tools-in-the-agentic-chatbot.md)
- **"How do you add human approval to a LangGraph agent?"** → Call `interrupt()` in the node or tool before the risky action, use a checkpointer, then resume the same thread with `Command(resume=decision)`. · [Human-in-the-Loop with interrupt()](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/06-human-in-the-loop-with-interrupt.md)
- **"Walk me through deploying an LLM app with CI/CD."** → Push triggers tests; on success, build a Docker image, push it to a registry tagged with the commit SHA, then have the server or service pull and restart with secrets from the environment. · [CI/CD to AWS with Docker and GitHub Actions](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/07-ci-cd-to-aws-with-docker-and-github-actions.md)
- **"Why would SQLite persistence break on Render's free tier?"** → The filesystem is ephemeral, so the DB file is wiped on every restart or deploy; use an external database like Postgres. · [Deploy on Render for Free with Docker](./07-agentic-ai/00-course/f-build-an-agentic-chatbot/08-deploy-on-render-for-free-with-docker.md)
- **"What problem does MCP solve?"** → It standardizes tool integrations, so one server works with every MCP-capable host, turning N×M custom integrations into N+M. · [What is MCP and Why Agents Need It](./07-agentic-ai/00-course/g-mcp-and-subgraphs/01-what-is-mcp-and-why-agents-need-it.md)
- **"When would you use a subgraph?"** → To encapsulate a multi-step unit (a research team, a reviewer) with private state, reuse it, and test it on its own. · [LangGraph Subgraphs](./07-agentic-ai/00-course/g-mcp-and-subgraphs/02-langgraph-subgraphs.md)
- **"What is an agent harness?"** → The scaffolding around the model: tools, context management, prompts, sandbox, permissions, observability and evals. · [Harness Engineering](./07-agentic-ai/00-course/i-safety-quality-ops/01-harness-engineering.md)
- **"How do you stop an agent from looping forever?"** → Hard max-iterations, a token/time budget, stuck detection on repeated calls, and a graceful partial-result exit. · [Loop Engineering](./07-agentic-ai/00-course/i-safety-quality-ops/02-loop-engineering.md)
- **"How is an FDE different from a solutions engineer?"** → SEs mostly work pre-sale on demos and POCs; FDEs build and ship production systems after the deal, embedded with the customer. · [Forward Deployed Engineer: Role and Skill Roadmap](./07-agentic-ai/00-course/j-fde-track/01-forward-deployed-engineer-role-and-skill-roadmap.md)
- **"What is ReAct?"** → A loop where the LLM alternates reasoning, tool calls and observing results until it can answer; it grounds answers in real data instead of memory. · [The ReAct Loop (reason → act → observe)](./07-agentic-ai/01-the-react-loop.md)
- **"How do agents remember things?"** → Short-term by replaying thread history; long-term by storing extracted facts and retrieving relevant ones into the prompt. · [Agent Memory (short-term vs Mem0/LangMem)](./07-agentic-ai/02-agent-memory.md)
- **"What are CrewAI's core abstractions?"** → Agent (role, goal, backstory, tools), Task (description, expected output), Crew (agents plus tasks plus process), and Flows for orchestration. · [CrewAI (role-based agent crews)](./07-agentic-ai/03-crewai.md)
- **"How does AutoGen model multi-agent work?"** → As a conversation: agents in a team take turns posting to a shared thread until a termination condition is met. · [Microsoft AutoGen (conversational multi-agent)](./07-agentic-ai/04-microsoft-autogen.md)
- **"What are the OpenAI Agents SDK primitives?"** → Agents, tools, handoffs, guardrails, run by a Runner, with tracing built in. · [OpenAI Agents SDK & Google ADK](./07-agentic-ai/05-openai-agents-sdk-google-adk.md)

## 8 · AgentOps, MCP & Production

- **"Why can't you just unit test an agent?"** → Outputs vary between runs and depend on the model and tool results, so you score a pass rate over an eval set, often with an LLM judge, instead of asserting exact outputs. · [Why AgentOps (agents are non-deterministic)](./08-agentops/01-why-agentops.md)
- **"MCP vs. plain function calling?"** → Function calling is how a model asks to run a tool; MCP is a standard for packaging and discovering tools so any app can use them without custom glue. · [MCP — Model Context Protocol](./08-agentops/02-mcp-model-context-protocol.md)
- **"MCP vs A2A in one line?"** → MCP gives an agent tools; A2A lets an agent delegate to another agent. · [A2A — Agent-to-Agent Communication](./08-agentops/03-a2a-agent-to-agent-communication.md)
- **"Logs vs traces?"** → Logs are isolated events; a trace links all steps of one request into a tree with timing, so you can see the path an agent took. · [Tracing & Observability (LangSmith)](./08-agentops/04-tracing-observability.md)
- **"Why choose Langfuse or Opik over LangSmith?"** → Open source and self-hostable, so sensitive traces stay in your infrastructure, and they're framework-agnostic. · [Tracing with Langfuse & Opik](./08-agentops/05-tracing-with-langfuse-opik.md)
- **"How do you evaluate an agent?"** → An eval set scored on outcome and trajectory, using code checks where possible and a validated LLM judge for open-ended parts, run in CI and on sampled production traffic. · [Agent Evaluation (DeepEval, eval sets)](./08-agentops/06-agent-evaluation.md)
- **"Can you prevent prompt injection with a better system prompt?"** → No. Reduce impact instead: least privilege, approval for risky actions, sandboxing and output checks. · [Agent Security (prompt injection, least-privilege)](./08-agentops/07-agent-security.md)
- **"Why containerize an LLM app?"** → Same environment everywhere, reproducible builds, and every cloud can run a container. · [Containerize & CI/CD (Docker + GitHub Actions on AWS)](./08-agentops/08-containerize-ci-cd.md)
- **"Why does my Render app fail with 'no open ports detected'?"** → It's listening on localhost or a hard-coded port; bind to `0.0.0.0` and `$PORT`. · [Free Deployment on Render](./08-agentops/09-free-deployment-on-render.md)
- **"Simplest way to host a containerized agent on GCP / Azure?"** → Cloud Run on GCP, Azure Container Apps on Azure. · [Cloud Deployment (GCP / Azure)](./08-agentops/10-cloud-deployment.md)
- **"What would you monitor for an LLM agent beyond normal API metrics?"** → Tokens and cost, steps and tool calls per run, tool error rate, online quality scores, refusal rate and drift. · [Production Monitoring (Prometheus, Grafana, ELK)](./08-agentops/11-production-monitoring.md)
